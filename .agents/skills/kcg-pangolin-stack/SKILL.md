# KCG Pangolin Stack

## Purpose

The Cianfhoghlaim platform runs **Fossorial Pangolin** on `arm1-oci` as the
private-resource router. Every HTTP service (Dagster, Convex, Komodo,
Infisical, FastAPI, HF Spaces, etc.) is exposed via a Pangolin
**private resource** with a `*.cianfhoghlaim.ie` subdomain. This
skill captures the 6-label pattern + the 4-host topology + the
`pangolin apply blueprint --api-key` CLI flow.

## When to use this skill

Use when you need to:

- "Add a new HTTP service to the KCG mesh"
- "Wire a new subdomain (`*.cianfhoghlaim.ie`)"
- "Debug a 502/404/401 from a Pangolin-routed container"
- "Migrate a stack from `localhost:<port>` to `*.cianfhoghlaim.ie`"
- "Add a Traefik middleware to a route (Tinyauth / secure-headers / rate-limit)"
- "Understand the difference between `pangolin.yaml` and `blueprint.yaml`"

## The 6-label pattern (the canonical shape)

Every `infrastructure/stacks/<name>/pangolin.yaml` follows this exact
shape. The 6 labels are:

```yaml
pangolin:
  private-resources:
    <name>:
      name: <name>                        # unique slug
      mode: http                          # "http" | "tcp" | "udp"
      full-domain: <sub>.cianfhoghlaim.ie # the FQDN
      destination-port: <port>            # the container's port
      protocol: http                      # "http" | "https"
      roles[0]: <role>                    # the Traefik role
```

### The 4 host tags (the topology)

| Tag | Host | Role | Examples |
|:--|:--|:--|:--|
| `host:bunchloch` | MacBook M4 (32GB) | Workload host (the personal machine) | Dagster, LanceDB, LiteLLM, oideachais FastAPI |
| `host:arm1-oci` | OCI arm instance (4 vCPU / 24GB) | Control plane | Komodo, Pangolin, Pocket ID, CrowdSec |
| `host:cax41-hetzner` | Hetzner CAX41 (16 vCPU / 32GB) | Storage (deferred) | Garage, Lakekeeper, Postgres |
| (no tag) | n/a | Reference stack (not deployed) | `infrastructure/stacks/logfire/`, `infrastructure/stacks/croilar-convex/` |

Every new Komodo stack on the user-named list MUST declare exactly
one `host:*` tag in `infrastructure/komodo/stacks/<name>.toml`. The
`bun run stack-doctor` script enforces this (see
`infrastructure/GOLD_STANDARD.md`).

### The 4 common Traefik middlewares

| Middleware | Purpose | When to use |
|:--|:--|:--|
| `tinyauth@file` | Pocket ID OIDC authentication | Any route that needs login (the FastAPI agents, the marimo dashboards) |
| `secure-headers@file` | HSTS + CSP + X-Frame-Options | Every HTTPS route (the default) |
| `rate-limit-api@file` | 100 req/s per IP | Public APIs (the Dagster code-locations, the Convex backend) |
| `rate-limit-auth@file` | 10 req/s per IP | Login endpoints (the BetterAuth `/api/auth/*` routes) |

## File anatomy: `pangolin.yaml` vs `blueprint.yaml`

- **`pangolin.yaml`** (per stack, in `infrastructure/stacks/<name>/`) —
  the **declarative** form. 6-label shape. Lives in git. Edited by
  humans.
- **`blueprint.yaml`** (per resource, generated by
  `pangolin apply blueprint --file`) — the **rendered** form.
  88-label shape. Lives in the Pangolin state store. Not in git
  (it'd duplicate the state).

When the user adds a new service, you write `pangolin.yaml` and run
`pangolin apply blueprint --file pangolin.yaml` to apply it.

## The CLI flow (4 commands)

```bash
# 1. Authenticate (one-time per session)
pangolin auth login --api-key $PANGOLIN_API_KEY

# 2. Validate the YAML locally
pangolin validate --file infrastructure/stacks/<name>/pangolin.yaml

# 3. Apply the YAML to the live Pangolin instance
pangolin apply blueprint --file infrastructure/stacks/<name>/pangolin.yaml

# 4. Verify the route resolves
curl -fsSL https://<sub>.cianfhoghlaim.ie/health
# Returns 200 + the service's `/health` JSON
```

## Worked example: add a new Dagster code-location

1. Add `infrastructure/stacks/oideachais-dagster/pangolin.yaml`:

   ```yaml
   pangolin:
     private-resources:
       dagster-oideachais:
         name: dagster-oideachais
         mode: http
         full-domain: dagster.cianfhoghlaim.ie
         destination-port: 3335
         protocol: http
         roles[0]: tinyauth@file
   ```

2. Add the Komodo stack definition at
   `infrastructure/komodo/stacks/oideachais-dagster.toml`:

   ```toml
   tags = ["host:bunchloch", "stack:dagster"]
   [services.dagster]
   image = "ghcr.io/cianfhoghlaim/oideachais-dagster:latest"
   ports = ["3335:3335"]
   ```

3. Apply:

   ```bash
   pangolin validate --file infrastructure/stacks/oideachais-dagster/pangolin.yaml
   pangolin apply blueprint --file infrastructure/stacks/oideachais-dagster/pangolin.yaml
   docker compose -f infrastructure/komodo/compose.yaml up -d
   ```

4. Verify:

   ```bash
   curl -fsSL https://dagster.cianfhoghlaim.ie/server_info
   ```

## Common failure modes

| Symptom | Cause | Fix |
|:--|:--|:--|
| 404 from `*.cianfhoghlaim.ie` | The `pangolin.yaml` was never applied | Run `pangolin apply blueprint --file ...` |
| 502 Bad Gateway | The container isn't running on the destination host | `docker ps` on the host; check the Komodo stack is on the right `host:*` tag |
| 401 Unauthorized | The route needs `tinyauth@file` but the user isn't logged in | Add the role `tinyauth@file` to the route + log in via Pocket ID |
| Connection refused on the host | The container is on a different host than the Pangolin proxy | Move the stack to the right `host:*` tag |
