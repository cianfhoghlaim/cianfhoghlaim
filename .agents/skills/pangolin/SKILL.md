# Pangolin - Network Infrastructure Platform

**Version:** 1.19.4 | **Last Updated:** 2026-06-29
**Upstream docs:** https://docs.pangolin.net (Mintlify-hosted)
**Repo:** https://github.com/fosrl/pangolin  (note: `fosrl`, not `fossoriale`)
**Newt connector:** https://github.com/fosrl/newt (v1.13.0+ required for browser SSH/RDP/VNC)
**Badger plugin:** v1.4.1+ (Traefik plugin required for 1.19 browser SSH)

## Overview

Pangolin is a network infrastructure management platform:

- **VPN**: WireGuard-based secure tunneling
- **Reverse Proxy**: Traefik integration for routing
- **Access Control**: Fine-grained network permissions
- **Service Discovery**: Automatic service registration
- **Docker Integration**: Container-aware networking

**Repository**: https://github.com/fosrl/pangolin  (renamed from `fossoriale`)

## Core Concepts

### 1. Architecture

```
┌────────────────────────────────────────────────┐
│                  Internet                       │
└───────────────────┬────────────────────────────┘
                    │
         ┌──────────▼──────────┐
         │      Traefik        │
         │   (Reverse Proxy)   │
         │     :80, :443       │
         └──────────┬──────────┘
                    │
         ┌──────────▼──────────┐
         │      Pangolin       │
         │   (Control Plane)   │
         │       :3001         │
         └──────────┬──────────┘
                    │
         ┌──────────▼──────────┐
         │      Gerbil         │
         │   (WireGuard VPN)   │
         │      :51820/udp     │
         └──────────┬──────────┘
                    │
    ┌───────────────┼───────────────┐
    ▼               ▼               ▼
┌───────┐      ┌───────┐       ┌───────┐
│Service│      │Service│       │Service│
│   A   │      │   B   │       │   C   │
└───────┘      └───────┘       └───────┘
```

### 2. Docker Compose Setup

```yaml
# compose.yaml
services:
  pangolin:
    image: ghcr.io/fosrl/pangolin:latest
    ports:
      - "3001:3001"
    volumes:
      - ./config:/app/config
      - pangolin-data:/app/data
    environment:
      - PANGOLIN_SECRET=${PANGOLIN_SECRET}
    networks:
      - pangolin

  gerbil:
    image: ghcr.io/fosrl/newt:latest
    cap_add:
      - NET_ADMIN
    ports:
      - "51820:51820/udp"
    volumes:
      - ./wireguard:/etc/wireguard
    sysctls:
      - net.ipv4.ip_forward=1
      - net.ipv4.conf.all.src_valid_mark=1
    networks:
      - pangolin

  traefik:
    image: traefik:v3.0
    command:
      - "--api.insecure=true"
      - "--providers.docker=true"
      - "--entrypoints.web.address=:80"
      - "--entrypoints.websecure.address=:443"
    ports:
      - "80:80"
      - "443:443"
      - "8080:8080"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
    networks:
      - pangolin

networks:
  pangolin:
    driver: bridge

volumes:
  pangolin-data:
```

### 3. Traefik Configuration

```yaml
# config/traefik.yaml
entryPoints:
  web:
    address: ":80"
    http:
      redirections:
        entryPoint:
          to: websecure
          scheme: https
  websecure:
    address: ":443"

providers:
  docker:
    exposedByDefault: false
    network: pangolin
  file:
    directory: /etc/traefik/dynamic
    watch: true

certificatesResolvers:
  letsencrypt:
    acme:
      email: admin@example.com
      storage: /letsencrypt/acme.json
      httpChallenge:
        entryPoint: web
```

### 4. Service Routing

```yaml
# Dynamic Traefik configuration
http:
  routers:
    my-service:
      rule: "Host(`service.example.com`)"
      entryPoints:
        - websecure
      service: my-service
      tls:
        certResolver: letsencrypt

  services:
    my-service:
      loadBalancer:
        servers:
          - url: "http://internal-service:8080"
```

### 5. WireGuard Client Configuration

```ini

```

### 6. Pangolin API Usage

```typescript
// Connect to Pangolin API
const pangolin = {
  baseUrl: "http://localhost:3001/api/v1",

  async createPeer(config: PeerConfig) {
    const response = await fetch(`${this.baseUrl}/peers`, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(config)
    })
    return response.json()
  },

  async listPeers() {
    const response = await fetch(`${this.baseUrl}/peers`)
    return response.json()
  },

  async getTraefikConfig() {
    const response = await fetch(`${this.baseUrl}/traefik-config`)
    return response.json()
  }
}

// Create new VPN peer
const peer = await pangolin.createPeer({
  name: "developer-laptop",
  allowedIPs: ["10.0.0.100/32"],
  dns: ["10.0.0.1"]
})

console.log("WireGuard config:", peer.config)
```

### 7. Service Labels for Traefik

```yaml
# docker-compose service with Traefik labels
services:
  api:
    image: my-api:latest
    labels:
      - "traefik.enable=true"
      - "traefik.http.routers.api.rule=Host(`api.example.com`)"
      - "traefik.http.routers.api.entrypoints=websecure"
      - "traefik.http.routers.api.tls.certresolver=letsencrypt"
      - "traefik.http.services.api.loadbalancer.server.port=3000"
    networks:
      - pangolin
```


## Network Patterns

### Pattern 1: Public + Private Services
```
Internet → Traefik → Public services (HTTPS)
                   ↓
VPN Peers → Gerbil → Private services (internal)
```

### Pattern 2: Zero-Trust Access
```
All services behind VPN
Traefik → authenticates → routes to services
Each service requires VPN connection
```

### Pattern 3: Hybrid Cloud
```
Cloud VPC ←→ Pangolin ←→ On-premise
           WireGuard tunnel
```

## Best Practices

1. **Separate Networks**: Use dedicated Docker networks for Pangolin
2. **TLS Everywhere**: Always use HTTPS with Traefik
3. **Peer Naming**: Use descriptive names (user-device-purpose)
4. **Regular Key Rotation**: Rotate WireGuard keys periodically
5. **Access Logging**: Enable Traefik access logs
6. **Health Checks**: Configure health checks for services
7. **DNS Configuration**: Use internal DNS for service discovery

## Troubleshooting

### VPN Not Connecting
```bash
# Verify UDP port is open
nc -vzu vpn.example.com 51820

# Check WireGuard config
wg show

# Check Gerbil container
docker logs pangolin-gerbil-1

# Verify kernel modules
lsmod | grep wireguard
```

### Service Not Accessible
```bash
# Check Traefik routing
curl http://localhost:8080/api/rawdata/routers

# Verify service is on correct network
docker network inspect pangolin

# Check service labels
docker inspect <container> | grep -A 20 Labels
```

### DNS Resolution Issues
```bash
# Test DNS resolution
dig @10.0.0.1 service.internal

# Check DNS configuration
cat /etc/resolv.conf

# Verify Gerbil DNS
docker exec pangolin-gerbil-1 cat /etc/resolv.conf
```

## KCG integration (canonical)

The Cianfhoghlaim platform uses Pangolin in a **convergence
architecture**:

```
┌──────────────────────────────────────────────────────────┐
│  Control plane (arm1-oci)                                │
│  → routing, identity (Pocket ID), orchestration (Komodo) │
└──────────────────────────────────────────────────────────┘
              ↓ WireGuard tunnel
┌──────────────────────────────────────────────────────────┐
│  Workload host (bunchloch MacBook M4)                    │
│  → memory-intensive workloads (LanceDB, Cognee,        │
│    LLM inference, local analytics)                        │
└──────────────────────────────────────────────────────────┘
```

All inter-tier communication is via WireGuard tunnels; no
inbound firewall ports.

### Pocket ID OIDC (admin SSO)

Pangolin uses **Pocket ID** for admin SSO. Admin users
authenticate via WebAuthn passkeys (no passwords).

```yaml
# Pangolin resource config (in komodo)
pangolin.oidc:
  provider: pocketid
  client_id: kcg-admin
  client_secret: ${INFISICAL:POCKETID_CLIENT_SECRET}
  issuer_url: https://pocketid.cianfhoghlaim.ie
```

### CrowdSec (anti-bruteforce)

The KCG Pangolin instance fronts CrowdSec for anti-bruteforce.
CrowdSec runs as a service **inside the Pangolin stack** at
`infrastructure/stacks/pangolin/compose.yaml`, not as a
standalone stack:

```yaml
# infrastructure/stacks/pangolin/compose.yaml  (the crowdsec service)
services:
  crowdsec:
    image: crowdsecurity/crowdsec:latest
    volumes:
      - ./config:/etc/crowdsec
    environment:
      COLLECTIONS: crowdsecurity/linux crowdsecurity/cf-cf-connect crowdsecurity/http-cve crowdsecurity/wordpress crowdsecurity/dovecot
```

### 6-label Docker pattern

Every Compose stack that exposes a web route uses the
canonical 6-label Pangolin resource:

```yaml
# infrastructure/stacks/<name>/pangolin.yaml
pangolin.private-resources.<name>:
  - name: <name>
    mode: http
    full-domain: <name>.cianfhoghlaim.ie
    destination-port: 8080
    protocol: http
    roles:
      - "<role-name>"
```

The 6 labels (in order): `name`, `mode`, `full-domain`,
`destination-port`, `protocol`, `roles[0]`. No variation.

### Multi-site HA

For the canonical KCG production deploy:

```yaml
pangolin.sites:
  - name: arm1-oci-prod
    url: https://pangolin.cianfhoghlaim.ie
    type: local
  - name: bunchloch-mac
    url: https://bunchloch.cianfhoghlaim.local
    type: local
```

### Tunneled Periphery access

For accessing a Periphery node behind NAT (e.g. a home
workstation running a dev stack):

```bash
# On the Periphery node
pangolin-cli tunnel-up \
  --site arm1-oci-prod \
  --port 8080 \
  --name bunchloch-dev
```

The Periphery node is then reachable at
`https://bunchloch-dev.cianfhoghlaim.ie` from the control
plane.

### 3-tier host convergence (the canonical KCG topology)

KCG runs across **3 hosts**, not 1 or 2. Pangolin
WireGuard tunnels wire them together:

| Tier | Host | Role | Pangolin role |
|:--|:--|:--|:--|
| **Control plane** | `arm1-oci` (Oracle Cloud ARM free tier) | Komodo (GitOps) + Pocket ID (OIDC) + CrowdSec (WAF) | Pangolin Core :3001 + Gerbil :51820/udp |
| **Storage** | `cax41-hetzner` (Hetzner cax41) | Garage S3 + Lakekeeper Iceberg REST + Postgres | Pangolin routing for `*.cianfhoghlaim.ie` |
| **Workload** | `bunchloch` (MacBook M4 Max) | Dagster + LiteLLM + the 70+ model servers | Tunneled via Newt → Gerbil |

The 3 hosts are wired by **Newt tunnel agents** (one per
host) and **Pocket ID OIDC SSO** (the single auth provider
for the whole cluster). See
`.agents/skills/bunchloch/SKILL.md` for the full
service map and `.agents/skills/convergence/SKILL.md`
for the 6 docker-compose categories that run on these hosts.
