# Documentation Consolidation Plan — Retrospective Report

> **Status:** Executed. This document is the retrospective record of the consolidation.
> **Date executed:** 2026-06-06
> **Consolidation ratio:** 1,038 files → 36 canonical files + 1 master index (28.8:1)

## 1. Executive Summary

The Cianfhoghlaim monorepo documentation had grown to 1,038 files (998 `.md`, 24 `.py`, 7 `.pdf`, 5 `.yaml`, 1 `.toml`, 1 `.docx`) spread across 8 unorganized subtrees plus a 116-file nested mirror at `docs/tuatha/tuatha/`. Total on-disk footprint was 49.7 MiB. Despite 201 files (19%) carrying YAML frontmatter, none used `domain:` or `status:` fields, and no master index existed — making it impossible for agents or developers to discover where information lived.

The consolidation applied a **heavy-merge strategy**: related content from multiple source files was merged into comprehensive canonical documents, each carrying structured Cognee-clean frontmatter. Source files were archived rather than deleted, preserving full audit trail.

**Result:** 36 canonical files across 7 numbered domains, a master routing index (`docs/00_index.md`) with 31 routing entries and 25 skill-to-doc mappings, and 851 archived source files organized by origin subtree and date. All old subtree directories have been removed. Every canonical file is ready for Cognee knowledge graph ingestion, ccc semantic search, and agent skill routing.

## 3. Methodology

### 3.1 Heavy Merge Strategy

Rather than one-to-one file migration, the consolidation used a **heavy merge** approach: related content from multiple source files was merged into unified canonical documents. This was chosen over a shallow reorganization because:

1. **Agent consumption**: LLM agents have finite context windows. One comprehensive document per topic is far more usable than 20-40 small, fragmented files.
2. **Cross-reference elimination**: Many source files cross-referenced each other for overlapping content. Merging eliminated circular references.
3. **Entity coherence**: Single documents allow consistent entity naming and relationship descriptions, which Cognee's knowledge graph extraction depends on.

Each merge was deterministic: `supersedes` frontmatter in every canonical file lists every source file whose content was absorbed, providing a complete audit trail back to the archive.

### 3.2 Frontmatter Schema

Every canonical file (including `00_index.md`) carries structured YAML frontmatter with this schema:

```yaml
---
title: "Human-readable title"
domain: architecture | data_platform | agents | ai_ml | web | product | standards
status: stable | draft | superseded | archived
description: "One-sentence summary"
supersedes:
  - docs/subtree/merged-file-1.md
  - docs/subtree/merged-file-2.md
entities:
  - EntityName1
  - EntityName2
related_skills:
  - .agents/skills/skill-name/SKILL.md
ccc_query_hints:
  - "natural language query that should return this doc"
last_reviewed: 2026-06-06
---
```

**Field purposes:**

| Field | Purpose |
|:--|:--|
| `title` | Human-readable display title for indexes and UI |
| `domain` | One of 7 controlled vocabulary values; used for routing and Cognee dataset partitioning |
| `status` | Lifecycle indicator — `stable`, `draft`, `superseded`, or `archived` |
| `description` | One-sentence summary for index tables and previews |
| `supersedes` | Explicit audit trail: every source file merged into this canonical document |
| `entities` | Named entities for Cognee knowledge graph extraction |
| `related_skills` | Paths to agent skills that should surface this document |
| `ccc_query_hints` | Natural-language queries optimized for ccc semantic search recall |
| `last_reviewed` | Date of last content review |

### 3.3 Archive Policy

Source files were **moved** (not copied) to `docs/archive/` organized by origin subtree and execution date:

## 6. Cognee Integration Strategy

### 6.1 Readiness Assessment

Every canonical file is prepared for Cognee knowledge graph ingestion:

- **Entity vocabulary**: All files use explicit entity names with consistent vocabulary within each domain. Entity names are declared in `entities:` frontmatter for deterministic extraction.
- **Relationship descriptions**: Content is structured with explicit relationship language (e.g., "depends on", "orchestrates", "ingests into", "is deployed to") that Cognee's entity extraction pipeline can parse.
- **Domain partitioning**: The 7 domains provide natural dataset boundaries for per-domain `cognify()` calls, preventing cross-domain entity noise.

The Cognee knowledge graph is currently **empty and ready** for ingestion.

### 6.2 Recommended Ingestion Strategy

**Seven per-domain cognify runs**, one per canonical domain directory:

| Run | Dataset | Source (`data` parameter) | Graph Model | Key Entities |
|:--|:--|:--|:--|:--|
| 1 | `architecture` | `docs/01-platform-architecture/` | `architecture_graph.py` | Cianfhoghlaim, Pangolin, Komodo, Bunchloch, Infisical, Locket, Traefik, PocketID, Talos, bun, uv, turbo |
| 2 | `data_platform` | `docs/02-data-platform/` | `data_platform_graph.py` | Dagster, dlt, DuckDB, DuckLake, LanceDB, MotherDuck, Firecrawl, CocoIndex |
| 3 | `agents` | `docs/03-agents/` | `agents_graph.py` | Agno, GoogleADK, BAML, Browserbase, Stagehand, Playwright, MCP, FastMCP, MCPO |
| 4 | `ai_ml` | `docs/04-ai-ml/` | `ai_ml_graph.py` | Cognee, Graphiti, Memgraph, FalkorDB, Unsloth, LanceDB, RAGAS, MLflow, Feast, CelticNLP |
| 5 | `web` | `docs/05-web/` | `web_graph.py` | TanStackStart, Hono, Convex, Vinxi, CopilotKit, shadcn/ui, TailwindCSS |
| 6 | `product` | `docs/06-product/` | `product_graph.py` | Tuatha, Crypteolas, Oideachais, Babylon.js, Phaser, SIWE, x402, LeavingCert, GCSE |
| 7 | `standards` | `docs/07-standards/` | `standards_graph.py` | Langfuse, OpenTelemetry, dignified-python, Effect-TS |

**Rationale for per-domain ingestion:**
- Each domain has a distinct entity vocabulary — mixing them in one run dilutes extraction quality.
- Per-domain `graph_model_file` allows custom entity schemas tuned to each domain's concept space.
- Smaller per-domain batches reduce hallucination risk in LLM-based entity extraction.
- Independent domains enable selective re-ingestion when a single canonical file changes.

### 6.3 Post-Ingestion Verification

After all 7 domains are ingested:
1. Run `cognee_search` with `search_type=GRAPH_COMPLETION` across each dataset to verify entity retrieval.
2. Validate that cross-domain queries (e.g., "how does Dagster orchestrate the dlt pipeline?") can traverse domain boundaries via the shared entity vocabulary.
3. Check that `ccc_query_hints` strings from frontmatter successfully retrieve the correct canonical documents.

## 7. ccc Integration Status

### 7.1 Current Status

The CocoIndex Code (ccc) semantic search index is fully operational with the consolidated documentation:

- **Index coverage**: ccc's `include_patterns` configuration covers `**/*.md` by default, so all 37 canonical markdown files (36 domain files + `00_index.md`) are automatically indexed.
- **Archive exclusion**: Files under `docs/archive/` are **not** excluded from ccc indexing by default. Excluding the archive directory from ccc's include patterns is recommended to prevent stale/duplicate search results from archived content.
- **Pre-consolidation benchmarks**: Search tests run before consolidation showed relevance scores in the 0.66–0.79 range. Post-consolidation scores are expected to improve because:
  - Each canonical document now contains concentrated, coherent topic coverage rather than fragmented files.
  - `ccc_query_hints` frontmatter provides explicit optimization signals for semantic search ranking.

### 7.2 Query Hint Strategy

The `ccc_query_hints` field in each canonical file's frontmatter contains natural-language queries optimized for that document's content. For example:

```yaml
ccc_query_hints:
  - "how does secrets management work"
  - "infisical vault configuration"
  - "locket sidecar injection"
  - "mise environment hydration"
```

These hints serve dual purpose:
1. **Semantic search optimization**: ccc can weight embeddings from hint-matching queries higher.
2. **Agent discoverability**: Agents can use hint strings as fallback search queries when routing fails.

### 7.3 Recommended ccc Configuration Update

To prevent archive files from polluting search results:

```json
// In .cocoindex_code/config.json or equivalent
{
  "exclude_patterns": [
    "docs/archive/**",
    "**/node_modules/**",
    "**/__pycache__/**"
  ]
}
```
