## TL;DR

Infisical is the **secrets manager** that backs every Cianfhoghlaim secret via the `infisical://dev-baile/<svc>/<key>` reference pattern. It's the single source of truth for 130+ secrets across the platform. The Locket sidecar (Pangolin-bundled) resolves these at container runtime.

The canonical Cianfhoghlaim 3-way contract:
1. **Source of truth** — `dev-baile` environment in Infisical
2. **Template** — `.infisical.env` (committed, contains only `infisical://...` URIs)
3. **Hydrated runtime** — `.env` (gitignored, written by `bun run secrets:init`)

**Hydration command**:

## Anti-patterns

1. Don't put secrets in `.env` directly — use `.infisical.env` URIs
2. Don't commit `.env` — it's gitignored
3. Don't use plaintext secrets in compose.yaml — use `${INFISICAL_SECRET}` interpolation
4. Don't share Infisical service tokens across hosts — use per-host scoped tokens
5. Don't skip `secrets:init` after editing `.infisical.env`
6. Don't use the legacy scoped tokens — Universal Auth is the current standard
7. Don't store INFISICAL_TOKEN in `.infisical.env` (chicken-and-egg) — use the Locket sidecar pattern

## Decision matrix

| Decision | Choice | Rationale |
|:--|:--|:--|
| Provider | Infisical (self-hosted on arm1-oci) | No external dependency |
| Auth method | Universal Auth | Modern + future-proof |
| Template format | `.infisical.env` (URI-only) | Git-safe + reviewable |
| Hydration | `bun run secrets:init` | Idempotent + scriptable |
| Per-stack access | Service tokens (per-host) | Least privilege |
| Backup | Daily Infisical DB snapshot | Off-vault safety net |
| Audit | Per-secret access logs | Compliance-ready |
