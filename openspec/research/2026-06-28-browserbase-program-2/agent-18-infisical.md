## TL;DR

Infisical is the **single source of truth** for every Cianfhoghlaim secret via the `infisical://dev-baile/<svc>/<key>` URI pattern. 130+ secret URIs across the monorepo flow through a three-way contract (template → vault → hydrated `.env`) orchestrated by `mise` directory hooks on the host and a **Locket sidecar** (`ghcr.io/bpbradley/locket:infisical`) at container runtime. The platform uses **Universal Auth** (POST `/api/v1/auth/universal-auth/login`) with machine identities for every non-human workload — periodic tokens + IP-allowlist-locked client secrets solve secret-zero. The Infisical CLI (`@infisical/cli`) and the **Kubernetes Secrets Operator** (with the v1beta1 `InfisicalStaticSecret` CRD replacing the deprecated `InfisicalSecret`) are the two recommended injection paths; the legacy `--token=<service-token>` flow is deprecated as of late-2025 in favour of `INFISICAL_TOKEN=$(infisical login --method=universal-auth …)`. Self-hosting ships in 6 flavours (Docker, Kubernetes Helm, Docker Compose, AWS ECS, GCP GKE, Linux package); we run the Docker Compose flavour at `https://infisical.cianfhoghlaim.ie` behind Pangolin with Pocket ID OIDC. Notably, **Infisical now publishes an MCP server card** at `/docs/.well-known/mcp/server-card.json` (per the response `Link` header on every docs page) — a discovery channel the next agent wave should explore.

## 1. Code patterns

### 1.1 The Cianfhoghlaim 3-way secrets contract

| Layer | File | Purpose | Lifecycle |
|:--|:--|:--|:--|
| **Source of truth** | `dev-baile` env in Infisical vault | Authoritative secret storage | Mutable via UI/API |
| **Template** (committed) | `.infisical.env` (950 lines, 130+ URIs) | `KEY=infisical://dev-baile/svc/key` mappings | Edited via PR |
| **Hydrated runtime** | `.env` (gitignored) | Resolved values for host processes | Regenerated by `mise` on `cd` |
| **Container injection** | `stacks/<name>/sidecar.yaml` Locket sidecar | Resolves URIs at container startup | tmpfs-backed, never on disk |

### 1.3 Programmatic vault sync — `scripts/init-vault.ts` (TypeScript SDK)

```typescript

await client.auth().universalAuth.login({
    clientId: CONFIG.infisicalClientId,

});

// scripts/init-vault.ts:99-115 — regex parses the .infisical.env template
const match = line.match(/^([A-Z0-9_]+)=.*?infisical:\/\/([^\/]+)\/(.*?)\/([^\/]+)$/i);
// captures: envKey, targetEnv, targetPath, targetName

```

Notable: the script handles **3 distinct error categories** with helpful remediation (401 → re-issue machine identity; 405 → wrong `INFISICAL_URL`; ENOTFOUND → service down) — a textbook *operational UX* pattern.

### 1.4 Locket sidecar (production-grade secrets injection)

From `infrastructure/stacks/infisical/sidecar.yaml:9-26` — this is the **canonical sidecar template** every other stack clones:

```yaml
services:
  locket:
    image: ghcr.io/bpbradley/locket:infisical
    user: "65532:65532"
    security_opt: [no-new-privileges:true]
    cap_drop: [ALL]
    command: ["--provider=infisical",
              "--infisical-client-id=${INFISICAL_CLIENT_ID}",
              "--infisical-client-secret=file:/run/secrets/infisical_secret",
              "--infisical-default-environment=${INFISICAL_ENVIRONMENT:-dev}",
              "--infisical-default-project-id=${INFISICAL_PROJECT_ID:-}",
              "--infisical-url=${INFISICAL_URL:-http://infisical-backend:8080}",
              "--map=/templates:/run/secrets/locket",
              "--mode=${LOCKET_MODE:-watch}"]
    secrets: [infisical_secret]
    volumes: ["./secrets.env:/templates/secrets.env:ro",
              "stack-secrets:/run/secrets/locket"]
  backend:
    depends_on: {locket: {condition: service_healthy}}
    env_file: [/run/secrets/locket/secrets.env]
volumes:
  stack-secrets: {driver: local, driver_opts: {type: tmpfs, device: tmpfs,
                   o: "uid=65532,gid=65532,mode=700"}}
```

5 key security patterns: (a) `uid 65532:65532` non-root; (b) `cap_drop: [ALL]` + `no-new-privileges`; (c) client secret loaded from Docker secret file (not env); (d) tmpfs volume with `mode=700`; (e) `depends_on: service_healthy` ensures the app waits for vault hydration.

### 1.5 Stack-side `secrets.env` (3-line minimal pattern)

```bash
# infrastructure/stacks/infisical/secrets.env:1-3
POSTGRES_USER={{ infisical://dev-baile/infisical/postgres_user }}
POSTGRES_PASSWORD={{ infisical://dev-baile/infisical/postgres_password }}
POSTGRES_DB={{ infisical://dev-baile/infisical/postgres_db }}
```

The `{{ }}` Jinja2-style wrapping is a **Locket-side convention** that lets the same template work as a raw `.env` (without `{{ }}`) or as a Locket-resolved secret (with `{{ }}`). Every stack follows this; `bun run stack-doctor` enforces it.

### 1.6 CLI Universal Auth token bootstrap (production pattern)

The recommended non-interactive auth flow, from the official docs:

```bash
# Single command: trade (client_id, client_secret) for short-lived bearer JWT
export INFISICAL_TOKEN=$(
    infisical login --method=universal-auth \
        --client-id=<identity-client-id> \
        --client-secret=<identity-client-secret> \
        --silent --plain
)
# All subsequent `infisical secrets`, `infisical run`, `infisical export` use INFISICAL_TOKEN
infisical run --env=dev --path=/apps/firefly -- npm run dev
```

Critical defaults baked into the CLI:
- `--silent` suppresses update banners (good for CI logs)
- `--plain` outputs the raw token (no JSON envelope)
- `--domain` flag or `INFISICAL_DOMAIN` env var must match self-hosted URL when not on US cloud
- `INFISICAL_API_URL` is legacy; `INFISICAL_DOMAIN` takes precedence

### 1.7 Kubernetes operator — v1beta1 (current) vs v1alpha1 (deprecated)

Three new CRDs split responsibilities cleanly (replaces the old monolithic `InfisicalSecret`):

| CRD | Purpose |
|:--|:--|
| `InfisicalConnection` (`secrets.infisical.com/v1beta1`) | Host + TLS config; referenced by other CRDs |
| `InfisicalAuth` (`secrets.infisical.com/v1beta1`) | Machine identity credentials; reused across CRDs |
| `InfisicalStaticSecret` (`secrets.infisical.com/v1beta1`) | Sync Infisical → Kubernetes `Secret` |

Helm install:
```bash
helm repo add infisical-helm-charts 'https://dl.cloudsmith.io/public/infisical/helm-charts/helm/charts/'
helm install --generate-name infisical-helm-charts/secrets-operator
```

Go-template engine `v1` is now mandatory (the old `includeAllSecrets` is gone); bulk-secret iteration is via a range loop over `.`.

### 1.8 Terraform provider schema (current)

`registry.terraform.io/providers/Infisical/infisical/latest/docs` — nested `auth` block supports 4 modes:

```hcl
provider "infisical" {
  host = "https://infisical.cianfhoghlaim.ie"  # or INFISICAL_HOST
  auth {
    universal {
      client_id     = "..."  # or INFISICAL_UNIVERSAL_AUTH_CLIENT_ID
      client_secret = "..."  # or INFISICAL_UNIVERSAL_AUTH_CLIENT_SECRET
    }
    # OR: aws_iam {} | kubernetes {} | oidc {} | token = "..."
  }
}
```

The legacy top-level `client_id` / `client_secret` / `service_token` attrs are **marked DEPRECATED** in the registry schema — migrate any old `.tf` to the `auth { … }` block.

## 5. Anti-patterns

1. **Don't put secrets in `.env` directly** — `.env` is gitignored; the only committed file is `.infisical.env` with URI references. `AGENTS.md:141` explicitly enforces this.
2. **Don't commit `.env`** — the runtime-hydrated file; would leak everything.
3. **Don't skip `bun run secrets:init`** after editing `.infisical.env` — vault and template will diverge silently.
4. **Don't store `INFISICAL_CLIENT_SECRET` in `.env`** — use Docker `secrets:` (file-mounted) per `sidecar.yaml:23-24`.
5. **Don't use `--token=<service-token>`** for non-legacy workloads — service tokens are deprecated in favour of Universal Auth + short-lived access tokens.
6. **Don't use `InfisicalSecret` (v1alpha1)** for new Kubernetes deployments — use `InfisicalStaticSecret` (v1beta1).
7. **Don't use the legacy top-level `client_id` / `service_token`** attrs in Terraform — use the nested `auth { universal {} | token = "" }` block.
8. **Don't share Universal Auth `client_secret` across hosts** — provision per-host scoped machine identities with trusted-IP allowlists.
9. **Don't use `docker run --env INFISICAL_TOKEN=...`** as a long-term solution — use the Locket sidecar so the token is auto-renewed.
10. **Don't put the Infisical CLI into a multi-stage Dockerfile with secrets** — the warning in docs/integrations/platforms/docker explicitly notes "Lack of persistence: Variables set in one build step are not automatically carried over" and "Security risk: It exposes sensitive credentials inside your container."
11. **Don't use `engineVersion: v0`** — the K8s operator removed it; `v1` is the only accepted value in `InfisicalStaticSecret` templates.
12. **Don't skip the `secrets:` block in sidecar.yaml** — Locket loads the client secret from a file mount (`file:/run/secrets/infisical_secret`), not from an env var.

## 8. Refactor opportunities

For the Cianfhoghlaim platform's secrets layer — informed by both the upstream Infisical product direction and our current `scripts/init-vault.ts` / `sidecar.yaml` patterns:

### 8.1 Migrate v1alpha1 K8s CRDs to v1beta1 (if/when we adopt K8s operator)

If we ever deploy the operator cluster-side (e.g. on `oci-k8s` worker pool), use `InfisicalStaticSecret` + `InfisicalConnection` + `InfisicalAuth` (3 CRDs) instead of the deprecated monolithic `InfisicalSecret`. Authentication becomes a **named, addressable resource** you can reuse across many `InfisicalStaticSecret` definitions — same caching, same credential rotation. Migration is a 4-step recipe documented at `/docs/integrations/platforms/kubernetes/overview#migrating-from-v1alpha1-to-v1beta1`.

### 8.2 Switch from CLI `--token` flow to native Universal Auth in every sidecar

Currently `scripts/init-vault.ts` does its own Universal Auth login. The cleaner pattern is to inject the `(client_id, client_secret)` pair as a Docker secret + let Locket do the OAuth exchange on every refresh (Locket supports both modes). This:
- Removes the bootstrap chicken-and-egg (no more `INFISICAL_TOKEN` in `.env`)
- Auto-renews tokens when they expire
- Eliminates the `scripts/init-vault.ts` `--silent --plain` hack

### 8.3 Add Infisical dynamic secrets for Postgres + Redis

The docs/integrations/app-connections layer supports **dynamic, ephemeral** credentials: every time a workload asks for `POSTGRES_DB_PASSWORD`, it gets a unique short-lived credential. This would replace the 7 manually-rotated Postgres password URIs in `.infisical.env` with a single dynamic endpoint. Trade-off: requires Infisical Enterprise license for the app-connection layer. Free-tier alternative: keep static URIs but enable the **PostgreSQL Credentials Rotation** flow (`docs/documentation/platform/secret-rotation/postgres-credentials`) with the dual-phase pattern (two active users, overlapping validity).

### 8.4 Adopt the first-party Infisical MCP server

Curl `https://infisical.com/docs/.well-known/mcp/server-card.json` and integrate with our `oideachais-mcp-filesystem` MCP server pattern. Two new tools become available: `infisical_secret_get(name, env, path)` and `infisical_secret_set(name, value, env, path)`. Saves us from maintaining the Bun-based `scripts/init-vault.ts` for interactive agent workflows (read-only auditing is the lowest-hanging fruit).

### 8.5 Pin the CLI version in sidecar installs before 2026-09-16

Infisical's Linux repo is migrating from Cloudsmith to `artifacts-cli.infisical.com` on **2026-09-16**. Update our `infrastructure/ansible/roles/infisical-cli/tasks/main.yml` (and any Komodo procedure that installs the CLI) to pin `infisical@0.41.x` and use the new apt repo URL. Without this, existing Linux dev hosts will fail to install/update the CLI after the cutoff.

### 8.6 Wrap the infisical `Link` header MCP discovery into a daily sync job

Use the existing `bun run scripts/` Bun CLI pattern to fetch `https://infisical.com/docs/.well-known/mcp/server-card.json` once per week and diff against the cached version. Surface the diff in our Langfuse `observability` dashboard so we know when Infisical adds new tools without us noticing.

### 8.7 Replace `{{ infisical:// … }}` and bare `infisical:// …` URI mix with single canonical form

The codebase has both `infisical://dev-baile/svc/key` (in `.infisical.env`) and `{{ infisical://dev-baile/svc/key }}` (in `stacks/*/secrets.env`). The `{{ }}` wrapping is a Locket-side convention; the bare form is what `init-vault.ts`'s regex parses. Add a `stack-doctor` rule (`scripts/stack-doctor.sh:64-67` is the prototype) that enforces one consistent form in each context (bare in `.infisical.env`, wrapped in `secrets.env`).

### 8.8 Provision per-host scoped machine identities (kill the universal-auth-anywhere anti-pattern)

`infrastructure/archive/HEALTH_REPORT-2026-06-12.md:225` flagged the `komodo-locket` Universal Auth client as lacking project-scope. Cure: provision one machine identity per stack with the `trustedIPs` locked to that stack's container CIDR. Pays for itself the first time a credential leaks (no lateral blast radius).
