## 4. Zotero — `https://www.zotero.org/` + API v3

### 4.1 API surface (`https://www.zotero.org/support/dev/web_api/v3/`)
- **Base URL:** `https://api.zotero.org` (HTTPS mandatory). Local API at `http://localhost:23119/api/` (no auth, no rate limit, served from the user's local Zotero desktop database).
- **Versioning:** Default v3; specify via `Zotero-API-Version: 3` header (recommended) or `?v=3` query param.
- **Auth:** NOT required for public libraries. For private: `Zotero-API-Key: P9NiFoyLeZu2bZNvvuQPDWsd` header, or `Authorization: Bearer <key>`, or `?key=<key>` query param. OAuth 1.0a supported; OAuth 2.0 "will be added" (announcements on `groups.google.com/group/zotero-dev`).
- **Resource shape:** `/users/{userID}/{collections|items|searches|tags}` or `/groups/{groupID}/…`. Multi-object requests return Atom 1.0 by default, JSON if `format=json` or `Accept: application/json`.
- **Other formats:** `atom`, `bib` (XHTML, max 150 items per request!), `json` (default), `keys` (newline-separated, no limit), `versions` (no limit), or any of `bibtex`, `biblatex`, `bookmarks`, `coins`, `csljson`, `csv`, `mods`, `refer`, `rdf_bibliontology`, `rdf_dc`, `rdf_zotero`, `ris`, `tei`, `wikipedia`.
- **Paging:** `limit` (default 25, max 100; * = export formats), `start` (0-based). Custom headers: `Total-Results`, `Link` (rel=first/prev/next/last/alternate), `Last-Modified-Version` (for conditional GETs).
- **Caching:** Conditional GET with `If-Modified-Since-Version: <libraryVersion>` → 304 Not Modified. Incremental fetch with `?since=<version>` returns only changed objects.
- **Rate limits:**
  - **`Backoff: <seconds>` header** in any response (incl. 200s) — server is overloaded, pause for N seconds.
  - **`429 Too Many Requests`** + `Retry-After: <seconds>` — back off exponentially, reduce concurrency.
  - **Hard limit: ≤ 4 concurrent requests** ("Clients should also generally make no more than 4 concurrent requests."). Stricter throttling + temporary blocks if repeated 429s.
  - **Local API has no rate limit** ("The local API does not currently apply rate limiting.").
- **Search params:** `q` (phrase-only quick search), `qmode` (`titleCreatorYear` default, `everything` for full-text), `itemType` (Boolean), `tag` (Boolean `||` `&&` `-`), `itemKey` (up to 50 per request), `since` (library version), `includeTrashed`.
- **Client libraries:** `tnajdek/zotero-api-client` (JS), `urschrei/pyzotero` (Python — most likely our match), `fcheslack/libZotero` (PHP/Python), `shazino/SZNZotero` (ObjC), `retorquere/zotero-sync` (TS).
- **HTTP status codes:** 200 OK, 304 Not Modified, 400/404/405 bad request, 500/503 server, 403 auth, 412/428 version conflicts, 417 unsupported `Expect` header, 429 rate limit.

## 5. arXiv — `https://arxiv.org/` + API + OAI-PMH

### 5.1 API surface (`http://export.arxiv.org/api/query`)
- **Base URL:** `http://export.arxiv.org/api/{method}?{parameters}` (note: **http, not https** — works fine but unencrypted).
- **Response format:** Atom 1.0 XML by default. Always 200, even on errors (errors are in the Atom feed).
- **Methods:** `query` is the only one. Parameters: `search_query`, `id_list`, `start` (0-based, default 0), `max_results` (default 10, **hard cap 30,000** in slices of max 2,000), `sortBy` (`relevance` / `lastUpdatedDate` / `submittedDate`), `sortOrder` (`ascending` / `descending`).
- **Field prefixes in `search_query`:** `ti` (title), `au` (author), `abs` (abstract), `co` (comment), `jr` (journal ref), `cat` (subject category), `rn` (report number), `id` (use `id_list` instead), `all` (all of the above).
- **Boolean:** `AND` `OR` `ANDNOT` (URL-escaped as `+AND+` etc.); `( )` `%28 %29` for grouping; `%22 %22` for phrase quoting.
- **Date filter:** `submittedDate:[YYYYMMDDTTTT+TO+YYYYMMDDTTTT]` (GMT, 24h to the minute).
- **Rate limit / politeness:** **"incorporate a 3 second delay in your code"** (per `info.arxiv.org/help/api/user-manual.html`). 30,000 results ≈ 2 minutes + 15 MB response.
- **Versions:** Append `vN` to the arxiv id (`cond-mat/0207270v2`).
- **No API key, no auth, no rate-limit HTTP headers, no 429s** — arXiv relies on the published 3-second-delay convention. Their monitoring is implicit ("play nice").
- **Caching:** "Search results do not change until new articles are added. Therefore there is no need to call the API more than once in a day for the same query. **Please cache your results.**" The `<updated>` element reflects midnight of the day of the call.
- **Entry extension namespace:** `xmlns:arxiv="http://arxiv.org/schemas/atom"` adds `<arxiv:comment>`, `<arxiv:journal_ref>`, `<arxiv:doi>`, `<arxiv:affiliation>`, `<arxiv:primary_category>` to the standard Atom `<entry>`.

### 5.2 OAI-PMH (`https://oaipmh.arxiv.org/oai`) — bulk harvesting
- **Base URL:** `https://oaipmh.arxiv.org/oai` (since March 2025 rewrite; old `http://export.arxiv.org/oai2` redirects).
- **Standard OAI-PMH 2.0 verbs:** `Identify`, `ListMetadataFormats`, `ListSets`, `ListRecords`, `ListIdentifiers`, `GetRecord`.
- **Metadata formats:** `oai_dc` (Simple Dublin Core), `arXiv` (arXiv-specific, latest version only, includes author names separated out + category + license), `arXivRaw` (close to internal format, **includes history of previous versions**).
- **Sets:** `group:archive:CATEGORY` — e.g. `cs:cs:AI` (one category), `physics:hep-th` (one archive), `physics` (all physics archives), or omit for everything.
- **Datestamps:** Track *modification* date, not submission. Earliest datestamp 2005-09-16 (pre-2005 articles share a single datestamp). **OAI-PMH does NOT support selective submission-date harvesting** — use `from=` incrementally for ongoing sync.
- **Update schedule:** New papers announced Sunday-Thursday ~10:30pm ET. The set structure was expanded in March 2025 (group:archive:CATEGORY format).

## Anti-patterns observed

- **Filename-as-provenance is not provenance.** `leabharlann/zotero.py:50-68` trusts a regex to extract arxiv_id from the filename. If the file is misnamed or moved, the link breaks. R15 (Zotero API) + R20 (arXiv API) replace the heuristic with verified, re-fetchable, citation-grade provenance.
- **No OpenData portal used for Crown Dependencies.** Only IoM + Jersey + Guernsey's HTML home pages are crawled. Jersey's `opendata.gov.je` has 110+ structured CSV/XLSX datasets, OGL-J-1.0-licensed, free JSON API — and we use **zero** of them. **R6 is the single highest-ROI refactor in this report.**
- **No bulk-harvest path for arXiv.** The REST API caps at 30k results, takes 2 min/call × 3s sleeps = 1.4 hours for 30k. The 2.4M-paper arXiv corpus needs OAI-PMH (R21) which is unbounded. Today we have no arXiv API integration at all.
- **No `User-Agent` header on the 3 IoM / Jersey / Guernsey crawls.** Volterra + SharePoint + GOSS all expect identifiable crawlers. Bare `python-requests` is treated as a bot and gets rate-limited or 503'd.
- **Sitemap reliance assumed but absent.** KCG's `crawl_website()` works best with `sitemap.xml`-driven discovery. None of the 3 Crown Dependencies publish a sitemap. R13 (GOSS search-index URL discovery) is the workaround.
- **No incremental cursor on the 3 Crown Dependencies.** Every `crawl_website()` call re-fetches from scratch. The IoM legislation portal is small enough to be tolerable, but Jersey's SharePoint + Varnish cache (with `age: 2929` headers — ~50 min TTL) makes incremental sensing easy with a URL+hash cursor.
- **No arXiv licence acknowledgement.** Required by API ToS for any product that displays arXiv data. R23 documents the requirement.
- **"Advanced Search" link to a 3rd-party VPS on `legislation.gov.im`.** `888295.vps-10.com` is a non-gov DNS — likely a legacy hosted search appliance, but a security/audit smell. R3 flags it.
