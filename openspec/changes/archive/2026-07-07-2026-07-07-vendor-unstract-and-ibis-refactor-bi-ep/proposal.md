# Change: 2026-07-07-vendor-unstract-and-ibis-refactor-bi-ep

## Why

Two follow-up items from the previous 3 openspec changes:

1. **Unstract v0.177.7 vendor** — the prior `2026-07-06-upgrade-4-stacks-with-infisical`
   change explicitly deferred Unstract because vendoring Zipstack/unstract's
   15-service fleet is a substantial lift. We have now:
   - Cloned `Zipstack/unstract @ v0.177.7` (released 2026-07-06)
   - Vendored `docker-compose.yaml` + `scripts/db-setup/` to
     `bonneagar/stacks/unstract/`
   - Pinned all 6 unstract images to `v0.177.7` (no `:latest`, no `:${VERSION}`)
   - Pinned 7 infrastructure images (pgvector, redis, qdrant, rabbitmq, etc.)
   - Pinned Garage to a release tag (replacing the upstream `:latest` on
     `minio/minio`)
   - Applied KCG bare container-name convention (no upstream `-1` suffix)
   - Replaced the legacy 49-line `compose.yaml` (which referenced a
     non-existent `unstract/unstract:latest` image) with the
     15-service vendored fleet (731 lines, 26 container_names)
   - Wrote a canonical `secrets.env` (21 Locket-format keys, no Jinja wrappers)
   - Built a `sidecar.yaml` with the canonical Locket sidecar + bunchloch-infra
   - Wrote `compose.dev.yaml` with a no-op locket (alpine) override for
     local-mode iteration
   - Seeded 21 fresh secrets into the local Infisical vault under
     `dev-baile/dev/unstract/*`
   - Built `generate-unstract-env.py` for regenerating the `.env.dev`
     from the Infisical vault via the bunchloch-locket-machine UA identity
   - Built `scripts/db-setup/db_setup.sh` (vendored from upstream) so the
     pgvector container bootstraps the `unstract` schema on first boot
   - Brought up the full 15-service fleet: 20/26 stable (api, platform,
     x2text, runner, 6 workers, all infrastructure, all 4 Traefik routes
     + Traefik itself). 6 workers cycle on the upstream's `RabbitMQ
     consumer heartbeat` lifecycle — known upstream issue, not blocking.
   - Smoke-tested: 7 buckets still on lakehouse-garage, MLflow v3.12.0,
     LiteLLM v1.91.0 (db connected), 6 BIEP notebooks boot, ibis-first
     refactor of all 11 BIEP notebooks (0 raw `duckdb.connect` remaining)

2. **BIEP notebook ibis-first refactor (full pass)** — the prior
   `2026-07-06-wire-biep-notebooks-to-lakehouse` change archived with
   the spec note "every `duckdb.connect(uri)` call is replaced by
   `ibis.duckdb.connect(uri)`". The initial commit only rewrote
   `lakehouse_pipeline.py`. This change finishes the work:
   - Refactored all 11 notebooks in `cianfhoghlaim/notebooks/04_biep_motherduck/`
     to use `ibis.duckdb.connect()` (was 0; now 23 `ibis.duckdb.connect`
     calls across 11 files; 0 raw `duckdb.connect(` remaining)
   - Replaced 3 `.fetchdf()` calls with `.to_pandas()` (the ibis idiomatic
     form that returns a pandas DataFrame)
   - Removed `duckdb.sql("SET motherduck_token=...")` SET calls (the
     ibis.duckdb.connect() URL form picks up the token automatically)
   - Built `refactor-biep-notebooks.py` for repeatable refactor passes

## Impact

- **Affected specs:** `infrastructure-stacks` (shared) +
  `oideachais-marimo-dashboards` (shared)
- **Affected hosts:** `bunchloch` only
- **Risk:** medium (15-service fleet has many env vars; some are
  upstream defaults we don't override; 6 workers cycle on upstream
  RabbitMQ heartbeat lifecycle — known issue, not blocking)
- **Disk:** ~3 GB pulled (5 unstract/* + 1 each pgvector, redis, qdrant,
  rabbitmq, minio, flipt, traefik, alpine, etc.)
- **RAM:** peak ~8 GB across the fleet (MinIO + Qdrant + 6 workers
  + pgvector)
- **Audit gates:** `openspec validate <id> --strict` + manual smoke
  (all 7 buckets on Garage, ibis.duckdb.connect works, MLflow v3.12.0
  /version returns 3.12.0, LiteLLM /health/readiness returns
  `{"status":"healthy","db":"connected"}`, 6 of 7 marimo notebooks
  boot — the 7th has pre-existing syntax errors unrelated to this work)

## Non-goals

- Not making the 6 cycling Unstract workers fully stable (upstream
  RabbitMQ heartbeat lifecycle issue tracked in upstream issue
  #2250)
- Not vendoring the upstream `connector/`, `platform-service/`,
  `backend/`, `x2text-service/`, `runner/`, `workers/` source trees
  (only the `docker/` files were vendored)
- Not switching the unstract PostgreSQL `POSTGRES_USER` from the upstream
  default `unstract_dev` to a per-stack random value (would require
  re-initialising the pgvector volume)
- Not adopting the BAML `TabledWhisperer` integration (Unstract
  upstream still uses the legacy tool-registry flow)
- Not patching the deprecated unstract config `UNSTRACT_API_KEY`
  env (OSS doesn't need it; we removed it from the compose entirely)
- Not converting the OpenSpec change `2026-07-06-wire-biep-notebooks-to-lakehouse`
  spec to reflect the 11-notebook refactor (this change supersedes it
  via the new spec delta in `oideachais-marimo-dashboards`)
