## MODIFIED Requirements

### Requirement: Stack Standardization

The system SHALL enforce a **single canonical 6-file contract** for every
`bonneagar/stacks/<name>/` directory. The contract files and their
canonical contents are:

1. `compose.yaml` — application services only. MUST NOT contain Locket
   references. MUST NOT contain `env_file: /run/secrets/locket/...`.
   MUST use the shell-wrapper pattern from `sidecar.yaml` for secret
   injection at runtime.
2. `sidecar.yaml` — Locket sidecar and shell-wrapper secret injection.
   MUST use one of two Locker images:
   `ghcr.io/bpbradley/locket:infisical` (canonical upstream) or
   `ghcr.io/cianfhoghlaim/locket-shim:infisical-<version>` (Cianfhoghlaim-internal
   workaround for the upstream snake_case bug). MUST declare one of
   three `LOCKET_MODE` values: `watch`, `park`, or `one-shot`.
3. `secrets.env` — Locket template file using the
   `{{ infisical:///key?env=dev-baile&path=/<service> }}` grammar.
   Legacy plain URI references of the form
   `infisical://dev-baile/<service>/<key>` SHALL be accepted but
   emit a `legacy-secret-syntax` warning.
4. `pangolin.yaml` — Traefik routing overlay (`http.routers` /
   `http.services`) OR Pangolin container labels of the form
   `pangolin.private-resources.<name>.*`.
5. `blueprint.yaml` — Pangolin EE root blueprint (`private-resources:`
   / `public-resources:` / `sites:`). SHALL be generated by the CLI
   from the stack manifest. SHALL NOT contain Komodo Resource Sync
   syntax. Roles SHALL be RBAC role names only — middleware
   references MUST appear in `pangolin.yaml` `middlewares:` arrays.
6. `.env.example` — non-secret documentation only. MUST NOT contain
   secrets. MUST contain every non-secret variable referenced from
   `compose.yaml`.

The `bonneagar/stacks/GOLD_STANDARD.md` document is the canonical
reference. The `bonneagar/GOLD_STANDARD.md` document SHALL be
removed or marked as deprecated.

The `cianfhoghlaim stack lint` validator SHALL fail the build if any
of the 6 files is missing or violates the contract.

#### Scenario: New stack passes cianfhoghlaim stack lint

- **GIVEN** a stack directory containing the 6 GOLD_STANDARD files
- **WHEN** `cianfhoghlaim stack lint <name>` runs
- **THEN** the validator SHALL succeed
- **AND** it SHALL emit zero legacy-pattern diagnostics

#### Scenario: Legacy secrets.env URI detected

- **GIVEN** `bonneagar/stacks/<name>/secrets.env` containing a line
  of the form `KEY=infisical://dev-baile/service/key`
- **WHEN** `cianfhoghlaim stack lint <name>` runs
- **THEN** the validator SHALL succeed with a `legacy-secret-syntax`
  warning
- **AND** the warning SHALL identify the file, line, and canonical
  Locket template replacement

#### Scenario: Komodo-shaped blueprint.yaml detected

- **GIVEN** `bonneagar/stacks/<name>/blueprint.yaml` containing
  Komodo Resource Sync syntax (`name:`, `type:`, `run_directory:`,
  `files:`)
- **WHEN** `cianfhoghlaim stack lint <name>` runs
- **THEN** the validator SHALL fail with a `legacy-blueprint-shape`
  diagnostic
- **AND** the diagnostic SHALL identify the file, line, and the
  Pangolin EE root blueprint replacement

#### Scenario: env_file parse-time pattern detected

- **GIVEN** `compose.yaml` containing `env_file: /run/secrets/locket/...`
  in any of the three syntactic forms (YAML list, inline scalar,
  inline array)
- **WHEN** `cianfhoghlaim stack lint <name>` runs
- **THEN** the validator SHALL fail with a `forbidden-env-file`
  diagnostic
- **AND** the diagnostic SHALL identify the file, line, and the
  shell-wrapper replacement from the 2026-07-27 fix

### Requirement: Locket shim image is Cianfhoghlaim-internal

The system SHALL publish and reference the Locket shim under the
Cianfhoghlaim-owned image namespace.

#### Scenario: Sidecar image is Cianfhoghlaim-owned

- **GIVEN** `bonneagar/stacks/<name>/sidecar.yaml` declaring a
  Locket shim image
- **WHEN** `cianfhoghlaim stack lint <name>` runs
- **THEN** the image reference SHALL be either
  `ghcr.io/bpbradley/locket:infisical` or
  `ghcr.io/cianfhoghlaim/locket-shim:infisical-<version>`
- **AND** references to `ghcr.io/cianfhoghlaim/locket-shim` SHALL fail validation
  with a `brand-renamed` diagnostic

## ADDED Requirements

### Requirement: Legacy secrets.env syntax accepted with warning

The system SHALL accept both the plain Infisical URI form and the
Locket template form in `secrets.env` files, but the plain URI form
SHALL emit a `legacy-secret-syntax` warning.

#### Scenario: Plain URI line in secrets.env

- **WHEN** a stack has `KEY=infisical://dev-baile/service/key` in
  `secrets.env`
- **THEN** the validator SHALL accept the line
- **AND** it SHALL emit a `legacy-secret-syntax` warning
- **AND** it SHALL suggest the canonical
  `KEY={{ infisical:///key?env=dev-baile&path=/service }}` form

#### Scenario: Locket template line in secrets.env

- **WHEN** a stack has
  `KEY={{ infisical:///key?env=dev-baile&path=/service }}` in
  `secrets.env`
- **THEN** the validator SHALL accept the line with zero warnings

### Requirement: Hetzner reference detection

The system SHALL fail `cianfhoghlaim stack lint` when any active
IaC file, stack README, or skill references `cax41`,
`cax41-hetzner`, or `security.hetzner`. The exclusion paths are
`.agents/skills_backup/` and `stedding/`.

#### Scenario: Hetzner reference in active stack README

- **WHEN** `bonneagar/stacks/<name>/README.md` contains
  `cax41-hetzner`
- **THEN** the validator SHALL fail with a `retired-host-reference`
  diagnostic
- **AND** the diagnostic SHALL list every offending file with line
  number

#### Scenario: Hetzner reference in frozen Pulumi program

- **WHEN** `bonneagar/iac/pulumi/hetzner/*.ts` contains
  `cax41-workloads`
- **THEN** the validator SHALL accept it (frozen historical record)

### Requirement: Cianfhoghlaim brand consistency

The system SHALL use `cianfhoghlaim` (lowercase) as the canonical
CLI, mise task, image, and documentation brand across the IaC and
stack layers.

#### Scenario: Bons or kcg token detected in an active IaC file

- **WHEN** any file under `bonneagar/` (excluding
  `.agents/skills_backup/`) contains the tokens `ghcr.io/cianfhoghlaim/locket-shim`,
  `bons:`, `ghcr.io/cianfhoghlaim/locket-shim:`, `kcg:`, or `KCGu`
- **THEN** the validator SHALL fail validation with a
  `brand-renamed` diagnostic
- **AND** the diagnostic SHALL list every offending file with line
  number

#### Scenario: New CLI uses cianfhoghlaim

- **WHEN** the deployment CLI is invoked
- **THEN** its command prefix SHALL be `cianfhoghlaim` (for example
  `cianfhoghlaim stack deploy <name>`)
- **AND** the CLI SHALL delegate to existing `iac:*` mise tasks for
  the IaC surface

### Requirement: Cianfhoghlaim CLI command surface

The system SHALL provide a `cianfhoghlaim` CLI with the following
subcommands: `stack lint|plan|deploy|verify|rollback`,
`secrets lint|verify|hydrate|seed`, `preflight`,
`topology validate`.

#### Scenario: Interactive deployment

- **WHEN** the user runs `cianfhoghlaim stack deploy <name>` in a
  TTY
- **THEN** the CLI SHALL render an Ink-based interactive
  dashboard
- **AND** it SHALL confirm deployment before applying
- **AND** it SHALL emit a deployment receipt on success

#### Scenario: Non-interactive deployment

- **WHEN** the user runs
  `cianfhoghlaim stack deploy <name> --non-interactive --yes`
- **THEN** the CLI SHALL NOT render an interactive Ink application
- **AND** it SHALL emit machine-readable JSON diagnostics and a
  non-secret deployment receipt
- **AND** it SHALL fail with exit code 1 on any preflight, health,
  or route check failure

#### Scenario: CI deployment

- **WHEN** `CI=true` is set in the environment
- **THEN** the CLI SHALL automatically behave as if
  `--non-interactive` was passed

## REMOVED Requirements

### Requirement: Two GOLD_STANDARD documents

The `bonneagar/GOLD_STANDARD.md` document at the IaC root and the
`bonneagar/stacks/GOLD_STANDARD.md` document at the stacks root
defined mutually-incompatible contracts. This requirement and the
two documents are superseded by the canonical single contract in
`MODIFIED Requirements > Stack Standardization` above.

**Reason**: The two documents diverged in their definitions of
`sidecar.yaml` (env_file vs shell-wrapper), `blueprint.yaml`
(Komodo Resource Sync vs Pangolin blueprint), and `secrets.env`
syntax (plain Infisical URI vs Locket template). A single canonical
contract is required for deterministic deployment.

**Migration**: `bonneagar/GOLD_STANDARD.md` SHALL be removed or
archived under `bonneagar/_archive/` with a pointer to
`bonneagar/stacks/GOLD_STANDARD.md`. The canonical contract is at
`bonneagar/stacks/GOLD_STANDARD.md`.
