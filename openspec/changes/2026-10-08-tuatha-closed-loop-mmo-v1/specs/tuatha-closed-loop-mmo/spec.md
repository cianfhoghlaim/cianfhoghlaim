# tuatha-closed-loop-mmo Specification

## Purpose
`tuatha-closed-loop-mmo` is the contract that wires the closed-loop
Tuatha British Isles Formative Assessment MMO demo end-to-end. The
demo lets the operator click a Mathematics Formative Session and see
a Tuatha PixiJS realm render with the celtic-art window chrome + sprite
banks generated by the 6-language asset pipeline (Plan 7) + linked via
the Cognee entity-asset graph (Plan 6) + queryable via DuckLake SQL
(Plan 5).

Per the 2026-10-08-tuatha-closed-loop-mmo-v1 saga change (Plan 8 of
`openspec/plans/2026-10-01-convergence-saga-v1.md`) — the final plan
in the convergence saga.

## ADDED Requirements

### Requirement: Per-subject realm asset (Mathematics-first launch)

The system MUST ship a Dagster asset `tuatha_realm_asset` that, given a
subject + language, returns the canonical realm JSON (the asset
metadata + sprite positions + window chrome URL + deity placement).
Mathematics is the first subject launched; the other 7 NCCA + 6
NCCA-adjacent subjects are added incrementally.

The realm JSON MUST include:
- `realm_id` (deterministic: sha256(subject + language)[:16])
- `subject` (e.g. "mathematics")
- `language` (en | ga | cy | gd | gv | kw | br)
- `sprite_bank` (list of sprite URLs from the per-language asset table)
- `window_chrome` (URL of the celtic-art window chrome)
- `deity_placement` (the Tuatha Dé deity for the subject + their treasure)
- `learning_outcomes` (the NCCA learning outcomes for the subject)
- `cognee_entities` (the linked entities from Plan 6)

#### Scenario: Mathematics realm JSON produced
- **WHEN** the operator runs `uv run python scripts/tuatha_demo.py --subject mathematics`
- **THEN** the realm JSON is produced with subject=mathematics + the canonical mathematics deity (The Dagda) + the cauldron of plenty treasure + 5 mathematics learning outcomes + 4 linked Cognee entities

### Requirement: Realm constructor ADK agent (the 26th in the fleet)

The system MUST ship `tuatha/agents/realm_constructor_agent.py` as an
ADK agent that builds Tuatha realms. The agent MUST use the canonical
ADK 2 Pillar 4 render_assets_node (from Plan 2) + the per-language
asset generation (from Plan 7) + the Cognee entity-asset linking
(from Plan 6).

#### Scenario: Mathematics realm constructor runs end-to-end
- **WHEN** the operator runs the realm constructor with subject=mathematics + language=en
- **THEN** the agent:
  1. Loads the Mathematics realm prompt (per the FIBO celtic-art window chrome per Plan 3)
  2. Generates the per-language asset via the GenerateIrishAsset BAML function
  3. Renders the asset via the litellm gateway
  4. Stores the asset in the per-language LanceDB table
  5. Links the asset to the Mathematics Cognee entities (Dagda + Cauldron + 4 concept entities)
  6. Builds the realm JSON with sprite_bank + window_chrome + deity_placement
- **AND** the agent returns `{"realm_id": "abc...", "asset_id": "def...", "cognee_linked": true}`

### Requirement: Quest pack generator (per-session)

The system MUST ship `tuatha/agents/quest_pack_agent.py` as an ADK agent
that generates the per-session quest pack. The quest pack MUST contain:
- `session_id` (deterministic: sha256(subject + language + timestamp)[:16])
- `subject`
- `language`
- `learning_outcomes` (5 outcomes per session)
- `quest_chains` (linked list of quests → outcomes → rewards)
- `celtic_window_chrome` (the celtic-art window chrome asset)

#### Scenario: Mathematics session quest pack
- **WHEN** the operator triggers a Mathematics formative session
- **THEN** the quest pack generator produces 5 NCCA-aligned quests
- **AND** each quest has a linked reward (the asset for that LO)
- **AND** the celtic window chrome is the first asset shown

### Requirement: Closed-loop demo (the visible win)

The system MUST ship a marimo dashboard at
`notebooks/dashboards/tuatha_realm_demo.py` + a CLI at
`scripts/tuatha_demo.py` that demonstrates the closed-loop. The CLI:
1. Triggers the realm constructor (subject + language)
2. Generates the quest pack
3. Displays the realm JSON (sprite_bank + window_chrome + deity + entities)
4. Returns the demo URL (or renders the demo in the terminal)

#### Scenario: Closed-loop demo runs end-to-end
- **WHEN** the operator runs `uv run python scripts/tuatha_demo.py --subject mathematics --language en`
- **THEN** the demo runs:
  1. Realm constructor → produces realm JSON with 4 sprites + window chrome + deity (The Dagda)
  2. Quest pack generator → produces 5 quests + 5 rewards
  3. Cognee linker → links 4 entities to the assets
  4. CLI displays the realm JSON (sprite_bank + window_chrome + deity_placement + linked_entities)
- **AND** the demo runs in < 30s (the offline dev mode with stub fallbacks)
