# Spec Delta: `croilar-data-engineering`

## MODIFIED Requirements

### Requirement: Dagster Asset Catalog (modified)

The system SHALL define Dagster assets that are generated **per (stream, source) pair** by a generic asset factory, reading from a Stream registry instead of hard-coded personas.

#### Scenario: Asset catalog is stream-driven

- **WHEN** the Dagster UI is opened
- **THEN** the asset catalog SHALL be generated by `make_dlt_asset(stream, source)` over the Stream registry
- **AND** asset keys SHALL be `(stream.id, source.type)` tuples — e.g. `("music", "spotify")`, `("teaching", "linkedin")`, `("cv", "filesystem")`
- **AND** no asset key SHALL contain the literal strings `aleyum`, `cianfhoghlaim`, or `carlcashman` (those are owner aliases, not data-layer ids)
- **AND** removing a `Stream` or `StreamSource` from the registry SHALL remove its assets on the next reload (no orphan code)

#### Scenario: Music pipeline assets (modified)

- **WHEN** the Stream registry contains `music` with `spotify`, `soundcloud`, `labels`, `artwork` sources
- **THEN** the asset catalog SHALL include `("music", "spotify")`, `("music", "soundcloud")`, `("music", "labels")`, `("music", "artwork")`
- **AND** each SHALL be materializable independently
- **AND** Spotify SHALL still target artist_id `2vLlk2CcC4NnN7yoNSTmX2`
- **AND** SoundCloud SHALL still target username `aleyummusic` (preserved as a source-level config, not a stream id)

#### Scenario: CV pipeline assets (modified)

- **WHEN** the Stream registry contains `cv` with `cv` and `filesystem` sources
- **THEN** the asset catalog SHALL include `("cv", "pdf_ingestion")`, `("cv", "extraction")`, `("cv", "search_index")`, and `("cv", "filesystem")`
- **AND** `("cv", "filesystem")` SHALL ingest from `/Users/cianmacandeisigh/dev/kings_college_galway/author_cian_deacy_lyons_mac_an_déisigh_uí_liatháin/`
- **AND** `("cv", "filesystem")` SHALL exclude the `zotero/` subdirectory (deferred to a future `("cv", "zotero_sql")` source)
- **AND** `("cv", "filesystem")` SHALL be marked `local_only=True` and SHALL NOT upload to R2
- **AND** `("cv", "extraction")` SHALL still use BAML `cv_extraction.baml` and `teaching_extraction.baml`

#### Scenario: Teaching pipeline assets (modified)

- **WHEN** the Stream registry contains `teaching` with `github`, `linkedin`, `researchgate` sources
- **THEN** the asset catalog SHALL include `("teaching", "github")`, `("teaching", "linkedin")`, `("teaching", "researchgate")`
- **AND** GitHub SHALL target username `cianfhoghlaim` (consolidated from the old `Yedya` persona)
- **AND** LinkedIn SHALL target the Cian Mac an Déisigh Uí Liatháin profile URL
- **AND** ResearchGate SHALL target the Cian Mac an Déisigh Uí Liatháin profile URL via a new `pipelines/researchgate/` source

#### Scenario: Cross-link assets (preserved)

- **WHEN** the Dagster UI is opened
- **THEN** the asset catalog SHALL still include `oideachais_assets_embedded` and `meaisinfhoghlaim_assets_embedded`
- **AND** these assets SHALL still read from the DuckLake catalog
- **AND** the read path SHALL still be read-only

### Requirement: BAML Extraction Schemas (modified)

The system SHALL define BAML schemas for the 4 extraction tasks: CV, teaching, identity, **researchgate (new)**.

#### Scenario: cv_extraction.baml compiles (preserved)

- **WHEN** `bun run baml-cli compile` is run
- **THEN** the BAML compiler SHALL still emit from `sruth/croilar/baml/cv_extraction.baml`
- **AND** the client SHALL still expose `ExtractCV`, `ExtractEducationEntry`, `ExtractAward`, `ExtractPublication`, `ExtractReference` functions

#### Scenario: teaching_extraction.baml compiles (preserved)

- **WHEN** `bun run baml-cli compile` is run
- **THEN** the compiler SHALL still emit from `teaching_extraction.baml`
- **AND** the client SHALL still expose `ExtractPlacement`, `ExtractStudentFeedback`, `ExtractCurriculumDesigned` functions

#### Scenario: identity_verification.baml compiles (preserved)

- **WHEN** `bun run baml-cli compile` is run
- **THEN** the compiler SHALL still emit from `identity_verification.baml`
- **AND** the client SHALL still expose `ExtractDocumentType`, `ExtractIssuingAuthority`, `ExtractExpiryDate` functions

#### Scenario: linkedin_profile_extraction.baml uses streamId (modified)

- **WHEN** `bun run baml-cli compile` is run
- **THEN** the `LinkedInProfile` class SHALL have a `streamId` field
- **AND** `streamId` SHALL be restricted to the enum `music | teaching | cv | research`
- **AND** the legacy `flowId` field and the `carlcashman` enum value SHALL be removed
- **AND** a new `ownerDisplayName: string` field SHALL be present

#### Scenario: researchgate_extraction.baml compiles (new)

- **WHEN** `bun run baml-cli compile` is run
- **THEN** the compiler SHALL emit TypeScript + Python client code from `sruth/croilar/baml/researchgate_extraction.baml`
- **AND** the client SHALL expose `ExtractResearchGateProfile` and `ExtractPublication` functions
- **AND** the `ResearchGateProfile` class SHALL have `streamId` and `ownerDisplayName` fields consistent with the LinkedIn schema

### Requirement: Stream Registry (new)

The system SHALL maintain a YAML-driven `Stream` registry that decouples stream id from owner identity.

#### Scenario: streams.yaml is the single source of truth

- **WHEN** the Stream registry is loaded
- **THEN** it SHALL be loaded from `sruth/croilar/config/sources.yaml` under the `streams:` key
- **AND** each entry SHALL have `id`, `owner`, `owner_display_name`, `r2_prefix`, `duckdb_dataset`, `sources: list[{type, config, local_only}]`
- **AND** the schema SHALL be validated by a Pydantic model in `sruth/croilar/_shared/streams.py`

#### Scenario: local-only streams skip R2

- **WHEN** a `StreamSource` has `local_only=True`
- **THEN** no DLT destination call SHALL write to R2 for that source
- **AND** all writes SHALL be confined to a local DuckDB file under `./data/local/`
- **AND** the `local_only` flag SHALL be visible in the Dagster asset metadata

### Requirement: Dagster Schedules (preserved)

The system SHALL schedule the assets to run on appropriate cadences.

#### Scenario: Daily music ingestion (preserved)

- **WHEN** the daily schedule fires at 03:00
- **THEN** all `("music", *)` assets SHALL be materialized in dependency order

#### Scenario: Weekly CV refresh (preserved)

- **WHEN** the weekly schedule fires on Sunday at 04:00
- **THEN** the `("cv", *)` assets SHALL be materialized in dependency order
- **AND** the `("cv", "search_index")` SHALL be re-built and the website search index SHALL be refreshed

#### Scenario: Monthly identity verification (preserved)

- **WHEN** the monthly schedule fires on the 1st at 05:00
- **THEN** the identity pipeline assets SHALL be materialized
- **AND** any expired identity documents SHALL be flagged in the Dagster UI

### Requirement: DuckLake Cross-DB Read (preserved)

The system SHALL use the existing DuckLake catalog for cross-DB reads.

#### Scenario: oideachais assets read via DuckLake (preserved)

- **WHEN** `oideachais_assets_embedded` materializes
- **THEN** Dagster SHALL query the DuckLake catalog for the latest `oideachais.curriculum` table
- **AND** the data SHALL be embedded via CocoIndex and stored in the `croilar_embeddings` table

#### Scenario: meaisínfhoghlaim assets read via DuckLake (preserved)

- **WHEN** `meaisinfhoghlaim_assets_embedded` materializes
- **THEN** Dagster SHALL query the DuckLake catalog for the latest `meaisinfhoghlaim.ocr` and `meaisinfhoghlaim.asr` tables
- **AND** the data SHALL be embedded and cross-linked to the CV / research subprojects

## REMOVED Requirements

### Requirement: Persona-Coupled Pipeline Defaults

**Reason**: The `aleyum` / `cianfhoghlaim` / `carlcashman` persona model conflates stream id with owner identity. The `carlcashman` persona is removed entirely; the `aleyum` / `cianfhoghlaim` personas survive as `owner` aliases under domain-`id` streams (`music` / `teaching`). All hard-coded `flow_id` strings, `aleyum` default usernames, and `AleyumSettings` class names are replaced by the Stream registry.

**Migration**: See `sruth/croilar/scripts/migrate-personas-to-streams.ts`. The script renames `notebooks/aleyum/` → `notebooks/streams/music/`, `notebooks/cianfhoghlaim/` → `notebooks/streams/teaching/`, rewrites imports, and updates the BAML `flowId` → `streamId`. After migration, `git grep aleyum|cianfhoghlaim|carlcashman` over the data layer SHALL return only the i18n tenant alias and the OG-image tenant class, both of which are UI branding (preserved by design).
