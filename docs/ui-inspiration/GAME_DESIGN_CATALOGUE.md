# Retro Educational Game Design Catalogue

> Generated by the 5th pipeline of `celtic-asset-generation`
> (`retro_design_patterns/`), per the
> `openspec/changes/retro-educational-game-asset-pipeline-v1/`
> change. The catalogue is the discovery surface for design patterns
> extracted from retro educational games — never the literal pixel
> art. Outputs are **conditioned on NCCA learning outcomes + bilingual
> EN + GA syllabus content**, not the source games' assets.

## What this catalogue is

A typed knowledge base of **design patterns** — UI layout, sprite
archetype, pedagogy pattern — extracted from retro educational games
by:

1. Driving the games through **headless libretro cores** (`mesen`,
   `snes9x`, `gambatte`, `mgba`, `genesis_plus_gx`, `pcsx_rearmed`),
   capturing PNGs at every scene transition + every 5 s of gameplay.
2. Segmenting the sprites + UI regions via **SAM3**
   (`facebook/sam3`) — each PNG decomposed into typed
   `SegmentationMask` records.
3. Extracting typed patterns via the canonical **Bolmo / Molmo2 /
   Qwen3-VL** VLM backbone + a BAML function
   `ExtractGameDesignPattern(image, game_ctx) -> GameDesignPattern`.
4. Embedding the patterns into the `cianfhoghlaim.retro.design_patterns`
   LanceDB table (BGE-large-en-v1.5, 1024-dim) via a v1 CocoIndex
   App that reuses the shared `_lifespan.py`.
5. Generating subject-conditioned **2D + 3D educational assets**
   for the Cianfhoghlaim Educational MMO:
   - **2D** (MMO v1, TanStack Start 2D client) — Flux /
     Z-Image-Turbo / Qwen-Image / FIBO via InvokeAI. Output:
     `stedding/asset_generation/2d/<subject>/<asset_id>.png`.
   - **3D** (MMO v2, Babylon.js — staged for the deferred client) —
     Microsoft TRELLIS.2-4B + Facebook SAM-3D-Objects. Output:
     `s3://cianfhoghlaim-asset-v2/3d/<subject>/<asset_id>.{glb,usdz}`.

## Starting library (v1)

| Game | Platform | Why it's here |
|:--|:--|:--|
| **Number Munchers** | NES (mesen) | Math drill — directly maps to `LC-MATHS-LO-2.x` |
| **Oregon Trail** | Apple II (MAME) — note: out of libretro v1 scope; placeholder | History / geography — covers westward-expansion vignettes |
| **Where in the World is Carmen Sandiego?** | Sega Genesis (genesis_plus_gx) + NES (mesen) | Geography + detective-puzzle pedagogy |

Each game in v1 must come from ROMs the operator already owns in the
ROMM library at `romm.cianfhoghlaim.ie` (or the new Drop-OSS/drop
library). Reuse is **design-pattern-only** — never literal pixel art.
Outputs are conditioned on NCCA LOs, not derived from source assets.

## How to read this catalogue

The marimo dashboard at
`cianfhoghlaim/notebooks/retro_game_design_catalogue.py` renders:

- A table of every `GameDesignPattern` (one row per `(game,
  level_index, scene_id)` triple) with the segmented sprite
  thumbnail, the bilingual EN + GA labels, the
  `transferable_to_subject` tag list, and a click-through link to
  the generated asset.
- A per-NCCA-subject explorer (one tab per subject in the 8
  NCCA subjects) listing the design patterns that map onto that
  subject.
- A per-pattern × per-source-game provenance view showing the
  source `retro_library` row, the source `retro_screenshots` row,
  and the copyright-safety CLIP-similarity + SSIM scores.

The Storybook workspace at `packages/game-assets-storybook/` shows
the **game-asset-facing variant** of the catalogue: per-NCCA-subject
sidebar categories, each rendering the pattern + at least one
generated asset.
